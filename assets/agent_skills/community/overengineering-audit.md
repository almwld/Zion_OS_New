# Overengineering Audit

Detect and analyze over-engineering, excessive abstraction, deep indirection, redundant wrappers, AI-generated slop, and file-system fragmentation in a codebase. This skill runs in **advisory** mode and serves to guide cleanup efforts via candidate recommendations.

## Core Auditing Pipeline

This audit is structured into three progressive tiers to maximize precision and minimize context bloat:

### Tier 1: AST, Redundancy, and File-System Scan
Run rapid structural and syntactic checks to locate candidates for over-engineering.

```bash
# Execute the Tier 1 Python analysis script using the canonical wrapper
$HOME/bin/python.cmd -c "
import ast, sys, os
from pathlib import Path

target = sys.argv[1] if len(sys.argv) > 1 else '.'
py_files = list(Path(target).rglob('*.py'))

print('=== Tier 1 Structural Audit ===')
for f in py_files:
    if any(p.startswith('.') or p.startswith('_') for p in f.parts): continue
    try:
        source = f.read_text(encoding='utf-8')
        tree = ast.parse(source)
        
        # Check 1: File-System Nesting / Path Fragmentation
        if len(f.parts) > 5:
            print(f'  [FS-DEPTH] {f} - Directory depth is {len(f.parts)-1} (deep nesting/fragmentation)')
        
        # Check 2: Class and function analysis
        classes = [node for node in ast.walk(tree) if isinstance(node, ast.ClassDef)]
        functions = [node for node in ast.walk(tree) if isinstance(node, ast.FunctionDef)]
        
        # Check 3: Comment density vs. AST logical node density
        lines = source.splitlines()
        comment_lines = sum(1 for line in lines if line.strip().startswith('#'))
        if len(lines) > 20 and (comment_lines / len(lines)) > 0.35:
            print(f'  [SLOP-RATIO] {f} - Comment density is {comment_lines/len(lines):.1%} (potential AI prose slop)')
            
        for cls in classes:
            methods = [node for node in cls.body if isinstance(node, ast.FunctionDef)]
            # Check 4: Single-method classes (excluding __init__)
            non_init = [m for m in methods if m.name != '__init__']
            if len(methods) > 0 and len(non_init) == 1:
                print(f'  [SINGLE-METHOD] {f}:{cls.lineno} - Class {cls.name} has only 1 functional method')
            
            for m in methods:
                # Check 5: Pass-through methods / redundant wrappers
                body = [node for node in m.body if not isinstance(node, (ast.Expr, ast.Pass)) or isinstance(node.value, ast.Constant)]
                if len(body) == 1 and isinstance(body[0], ast.Return):
                    ret_val = body[0].value
                    if isinstance(ret_val, ast.Call) and isinstance(ret_val.func, ast.Attribute) and ret_val.func.attr == m.name:
                        print(f'  [WRAPPER] {f}:{m.lineno} - Redundant pass-through method: {cls.name}.{m.name}')
    except Exception as e:
        pass
" "$TARGET"
```

### Tier 2: Call-Graph & Indirection Scan
Detect pass-through files, empty facade packages, and deep indirection (A calls B, which calls C, which has no additional logic).

- **Empty Facades**: Directories containing only imports (`__init__.py` with multiple imports but no actual implementations, or files that re-export modules solely to create a new folder namespace).
- **Deep Indirection**: Check for files where the average line length is extremely short and the functions do nothing but redirect parameters to other libraries or classes.

### Tier 3: High-Value Semantic Review
Select the top **5–10 candidate files/directories** surfaced in Tiers 1 & 2 and run a targeted LLM inspection.
- **Factory Abuse**: Creating factories to instantiate single classes or when direct instantiation is cleaner.
- **Premature Generalization**: Design patterns (Strategy, Provider, Abstract Base Classes) applied to simple or single-use workflows.
- **Slop Boilerplate**: Prolix helper classes, configuration managers, or boilerplate files generated to satisfy imaginary requirements.

## Rules & Invariants

1. **Advisory Mode Constraint**: This skill is strictly advisory. Do **NOT** perform any destructive changes, file moves, or code edits automatically.
2. **Confirmation Gate**: Remediations must be presented as options (`[ ] A1`, `[ ] B1`). Any proposed next action must end with: `— confirm to proceed?`
3. **No Placeholders**: Every finding must cite actual paths and specific AST node structures or file layouts.
4. **Three-Line Rule**: Remember, three lines of repeated code is almost always better than a premature wrapper or factory abstraction.
